# Договор хранения: номер, раздел «Клиенты», кнопка из записи

> Source: Реализация в backend (план `.claude/plans/storage-contract-number-and-clients.md`), изменение кода
> Collected: 2026-09-18
> Published: Unknown

## Что сделано

Три доработки вокруг домена Storage:

1. У договора хранения появился **номер** — ID с ведущими нулями до пяти знаков (`00042`).
2. В панели появился **раздел «Клиенты»** (корневой, вне кластеров): список, создание, карточка.
3. В форме записи на шиномонтаж появилась **кнопка «Создать договор хранения»**, ведущая на форму
   договора с предзаполненными данными записи.

## Решения (согласованы с пользователем в обсуждении плана)

1. **Номер — производная от ID, а не колонка.** Аксессор `StorageContract::getNumberAttribute()`
   (`str_pad($id, 5, '0', STR_PAD_LEFT)`); ID не меняется, копия в БД завела бы второй источник правды.
   Виден в листинге первой колонкой и в заголовке карточки («Договор № 00042 — Петров Иван»).
2. **`booking_id` не заводим** (выбор пользователя): договор по-прежнему знает только клиента.
   Сценарий «сдал колёса при визите» наступил, но связи не нужно ни одной механике; предзаполнение
   идёт адресом формы. Цена решения: по уже заведённым договорам связь с визитом не восстановить.
   Пометка внесена в ADR 0026.
3. **Клиент — полноценный раздел панели** (вариант «модалка в поле» отклонён пользователем): список,
   создание, карточка. Кнопка «Создать пользователя» на форме договора открывает форму клиента
   **в новой вкладке** — иначе заполненный договор теряется; после создания клиент сразу находится
   поиском в поле «Клиент» (Select ищет на сервере).
4. **Триггер кнопки в записи — категория услуги** (`ServiceCategory::Storage`), не название:
   «Сезонное хранение шин» правится в справочнике услуг, категория — нет.
5. **Создание записи и договора в одном действии**: кнопка на странице создания сохраняет запись
   (штатная валидация + `CreateAdminBooking` — клиент ищется/создаётся по телефону), затем уводит
   на форму договора. На правке запись уже сохранена — кнопка сразу уводит.

## Предзаполнение формы договора

`CreateStorageContract` принимает адресом три параметра (`#[Url]`): `user_id`, `starts_on`
(дата слота записи), `price` (итог строки хранения: цена × количество, рубли). Значения собирает
`App\Filament\Support\StorageContractPrefill::paramsFor(Booking)`; он же (`hasStorageService`)
решает по состоянию репитера «Услуги», показывать ли кнопку. Пустые значения в адрес не попадают.

Кнопки живут в ряду действий формы: у создания записи — `getFormActions()` (сверх «Создать»/«Отмена»),
у правки — новый хук трейта `SavesAndCloses::getExtraFormActions()` (сверх «Сохранить»/«Сохранить
и закрыть»/«Отмена»).

## Раздел «Клиенты»

`App\Filament\Resources\UserResource` (корневой, вне кластеров; `$navigationSort = 40` — после
кластеров). Листинг: ФИО (поиск по частям), телефон, почта, дата регистрации. Форма: фамилия, имя
(обязательно), отчество, телефон, почта. Пароля нет — входа клиента в панель нет, клиент опознаётся
телефоном и SMS-кодом; удаления нет — на клиента ссылаются записи и договоры (FK restrict).

Телефон канонизируется в «7XXXXXXXXXX»: `dehydrateStateUsing(Phone::normalize)` при записи
и собственная проверка уникальности **по канону** (штатный `unique()` сверял бы сырой ввод —
«8 912…» и «79123456789» разошлись бы и дубль упал бы ошибкой БД).

## Проверки

- Красный прогон: `17 failed, 11 passed` — из новых зелёный только страж-тест «без параметров
  адреса поле клиента пустое»; остальные падали по делу (нет аксессора `number`, нет кнопок,
  нет страниц `UserResource`).
- Зелёный: 28 тестов тест-листа, полный набор `658 passed` (было 640), PHPStan — 0 ошибок, Pint — чисто.
- Грабли тестов: `callAction('имя')` не запускает действие со строковым `action('метод')` —
  `Action::getActionFunction()` для строки возвращает null, обработчик не зовётся вовсе; в браузере
  клик зовёт метод напрямую. Рабочая форма — `->call('метод')` + `assertActionVisible`/`assertSee`
  (как у «Сохранить и закрыть»).
- Тесты: `tests/Unit/Models/Storage/StorageContractTest.php` (номер), `UserResourceTest.php`
  (канон телефона, дубль, отсутствие удаления, поиск), `BookingStorageContractFlowTest.php`
  (видимость кнопки по категории, сохранение и переход, невалидная форма, параметры адреса, правка),
  `StorageContractResourceTest.php` (+5 кейсов: номер в списке и заголовке, предзаполнение, кнопка клиента).
