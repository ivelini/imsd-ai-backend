# Точное время внутри часа, проверка совпадения и цветной статус слота

> Source: Проект, сессия 2026-09-15 (план `.claude/plans/booking-slot-time-and-status.md`, прогоны там же)
> Collected: 2026-09-15
> Published: 2026-09-15

## Запрос

1. В `/panel/booking/slots` статус: открыт — зелёный круг, закрыт — красный (было перевёрнуто: закрытый слот
   рисовался зелёной галочкой с подписью «Открыт»).
2. При сохранении и обновлении записи — проверка совпадения времени: вторую запись на то же время сохранять нельзя.
3. В записи — поле «Время»: слот на 14:00 → выбор 14:00–14:59.
4. Запись, вставшая ровно на начало часа (14:00), автоматически закрывает слот.

## Решения (согласованы с пользователем)

- **Час занимает только запись ровно на его начало.** Запись на 14:30 час не закрывает: время 14:00 остаётся
  свободным для сайта. Чекбокс «Закрыть слот с привязкой к записи» убран — закрытие определяет время; вручную
  закрыть/открыть по-прежнему можно кнопкой на сетке.
- **Шаг времени — каждая минута** (14:00…14:59); выбор слота подставляет его начало.
- **Минуты выбирает только оператор**: сайт бронирует час целиком (ADR 0016), но проверка совпадения действует
  и там — клиент на занятое время получает отказ, а не вторую запись.
- Отменённые записи время не держат; правимая запись сама себе времени не занимает.
- Миграций нет: время ложится в существующее `bookings.start_time` (`time`), у слота уже есть `is_closed`
  и привязка `booking_id`.

## Реализация

| Место | Что |
|---|---|
| `Slot::startsHour(string $startTime)` | «время ровно на начало часа слота» — одно правило для всех путей |
| `Preconditions\Booking\EnsureSlotTimeIsFree` | запись на то же время в том же слоте (кроме отменённых и кроме правимой) → `DomainException` 409; вызывается под `lockForUpdate` слота |
| `CreateAdminBooking` | блокировка слота → проверка времени → `start_time` из формы → запись на начало часа закрывает и привязывает слот (чужую привязку не перезаписывает) |
| `UpdateAdminBooking` | блокировка слота, проверка времени (кроме себя), `start_time` из формы, `syncSlotClosure`: встала на начало часа — закрыть и привязать; уехала внутрь часа — снять **своё** закрытие (чужую привязку и ручную причину не трогает) |
| `ConfirmBooking` (сайт) | та же проверка времени — час мог быть переоткрыт вручную |
| `BookingForm` | Select `start_time` (варианты по часу слота: на создании — выбранного, на правке — слота записи), `formatStateUsing`/`dehydrateStateUsing` между `HH:MM` и `HH:MM:00`; хук выбора слота подставляет начало часа; чекбокс `close_slot` убран |
| `EditBooking` | ловит `DomainException` → уведомление и остановка сохранения (как страница создания) |
| `SlotsTable` | `IconColumn` состояния: открыт — `CheckCircle`/зелёный, закрыт — `XCircle`/красный |
| `DemoBookingSeeder` | записи на начало часа закрывают слот; пары «слот + время» не повторяются (правило домена в демо-данных) |

## Грабли

- **Сравнение на билдере запроса молча ничего не фильтрует.** В листинге записей было
  `fn (Slot $slot) => $slot->date >= now()->startOfDay()` внутри `whereHas`: Eloquent передаёт в замыкание
  **билдер**, не модель, поэтому свойство `date` — undefined, сравнение ничего не отсекает (и типизация модели
  в замыкании роняет страницу `TypeError`). Рабочая форма — `fn (Builder $q) => $q->where('date', '>=', now()->startOfDay())`.
- Статус `Arrived` («Клиент приехал») убран из `BookingStatus`: статусная машина — `confirmed → done / cancelled / no_show`.
  ФТ-12 в ТЗ и страницы вики описывали старый набор — поправлены.
