# ФИО клиента по частям: `users` + заполнение и правка из записи

> Source: Проект, сессия 2026-09-15 (план `.claude/plans/users-full-name-parts.md`, прогоны там же)
> Collected: 2026-09-15
> Published: 2026-09-15

## Запрос

Завести в таблице `users` поля для ФИО — каждое по отдельности; при создании и правке записи дать
возможность заполнять и менять ФИО.

## Решения (согласованы с пользователем)

- **Колонка `name` остаётся именем человека** — это и есть «имя» из ФИО; добавлены `surname` (фамилия)
  и `patronymic` (отчество). Никакого `first_name` и никаких переименований: схема сразу правильная,
  база пересоздаётся, сидеры правятся.
- **ФИО заполняет только оператор в панели.** Сайт по-прежнему присылает имя одной строкой — оно ложится
  в `name`; фронт и контракт сайта не трогаем.
- **Показ — склейка «Фамилия Имя Отчество»** (аксессор `User::full_name`, пустые части опускаются):
  заголовок записи, карточка слота, листинги панели и ответ API (`user.name` — по-прежнему одна строка).
- **Обязательны имя и фамилия**, отчество — как получится (оператор по звонку часто знает не всё).
  В БД `surname`/`patronymic` nullable: сайт фамилию не спрашивает, обязательность держит форма панели.

## Реализация

| Место | Что |
|---|---|
| Миграция | `users` + `surname`, `patronymic` (nullable); `name` не трогается |
| `User::getFullNameAttribute()` | склейка для показа: «Фамилия Имя Отчество», пустые части опускаются |
| `BookingForm` | три поля (Фамилия, Имя, Отчество) на создании **и** на правке; на правке подставляются из карточки клиента (`mutateFormDataBeforeFill`) |
| `CreateAdminBooking` | `updateOrCreate` по телефону: карточка клиента следует за вводом оператора; пустое отчество прежнее значение не затирает (очистить можно на правке, где поля предзаполнены) |
| `UpdateAdminBooking` | правка ФИО обновляет карточку клиента — один телефон, один клиент, поэтому ФИО меняется и в остальных его записях |
| `BookingClientResource` | `name` = `full_name` — контракт сайта не меняется |
| `BookingsTable`, `SlotsTable`, `Slots/BookingsRelationManager` | клиент показывается склейкой; поиск в списках идёт по частям (`whereHas('user', …)` — склейка не колонка) |
| `UserFactory`, `DemoBookingSeeder` | фабрика даёт только имя (как клиент с сайта); сидер разбирает «Иван Петров» на имя и фамилию |

## Заметки

- ФИО клиента в записи не снимок: это карточка клиента (ADR 0017 фиксирует снимком параметры авто и цену,
  а имя всегда было свойством `users`).
- `documentations/db-schema.md` обновлён: ФИО по частям у `users`, у `bookings.start_time` описано точное
  время внутри часа, из статусов убран `arrived`.
