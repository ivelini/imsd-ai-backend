# Хранение колёс: договор хранения — новый домен Storage

> Source: Реализация в backend (план `.claude/plans/storage-contracts.md`), изменение кода
> Collected: 2026-09-17
> Published: Unknown

## Что сделано

Новый функционал «хранение колёс»: на клиента (`users`) заводится **договор хранения** — срок от/до,
стоимость и позиции (что оставлено на хранении: наименование + описание с особенностями).

## Решения (согласованы с пользователем в обсуждении плана)

1. Договор **самостоятельный** — связи с записью на шиномонтаж нет (колёса часто привозят без визита);
   появится сценарий — добавим nullable-ссылку миграцией.
2. Стоимость — **ручная сумма** за весь срок (снимок, копейки). Расчёт по прайс-кубу «Хранение»
   (`ServiceCategory::Storage` — категория разовой услуги в прайсе) отложен: прайс описывает работу,
   а не сезонный договор.
3. Статус `active` / `closed` + дата фактической выдачи (`closed_at`); **закрывает оператор** кнопкой
   «Выдать колёса» в листинге — автоматики по срокам нет.
4. Домен — отдельный **Storage** (`app/Models/Storage/`, `app/Enums/Storage/`), раздел панели — кластер
   «Шиномонтаж», новая группа «Хранение» (`BookingGroupEnum::Storage`).
5. Позиция — ровно два поля (наименование, описание); количество/тип/радиус не заводим.

## Схема

- `storage_contracts`: `user_id` (FK users, restrict), `starts_on` / `ends_on` (date), `price`
  (копейки, `MoneyCast`), `status` (active/closed), `closed_at` (timestamp nullable),
  `operator_id` (FK admins, nullOnDelete); индексы `status`, `ends_on`.
- `storage_items`: `storage_contract_id` (cascade), `name`, `description` (text nullable).
- Модели: `StorageContract` (belongsTo `User`, `Admin`-оператор, hasMany `items`), `StorageItem`;
  у `User` — `hasMany storageContracts`.

## Панель

`StorageContractResource` (кластер «Шиномонтаж», группа «Хранение», сортировка 30): форма — клиент
(`Select` со связью, поиск по имени/фамилии/телефону), срок с/по (`DatePicker`, `afterOrEqual` —
равенство дат допустимо: сдал и забрал в один день), стоимость (рубли → `Money`), позиции —
`Repeater` **со связью** (Filament синхронизирует строки по id: правка обновляет, убранная удаляется,
новая создаётся), `required` + `minItems(1)`. Статуса в форме нет — закрывает действие таблицы.
Таблица: клиент (поиск по частям ФИО), телефон, срок с/по, стоимость, число позиций, состояние (бейдж);
действия «Выдать колёса» (видно только у активных), правка, удаление. Страница правки — с кнопкой
«Сохранить и закрыть» (`SavesAndCloses`). Оператора проставляет `CreateStorageContract`
(`auth('admin')->id()`), поля в форме нет.
