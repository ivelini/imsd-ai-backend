# Печать договора хранения: PHPWord, нумерация со 100

> Source: Реализация в backend (план `.claude/plans/storage-contract-print.md`), изменение кода
> Collected: 2026-09-18
> Published: Unknown

## Что сделано

Оператор на карточке договора (кнопка «Распечатать договор») получает .docx: договор и акт
приёма-передачи с номером, клиентом, телефоном, сроком, стоимостью и позициями. Договоры нумеруются
со 100, в листинге договор ищется по номеру.

## Решения (согласованы с пользователем в обсуждении плана)

1. **Генерация — пакет `phpoffice/phpword`** (решение пересмотрено против первой версии плана, где
   писали свой XML-движок): проверено на настоящем шаблоне — `fixBrokenMacros()` склеивает run-ы,
   расколотые Word'ом, `cloneRow()` размножает строку таблицы и нумерует **все** макросы строки
   (`item_id#1`, `item_name#1`, `item_desc#1`).
2. **Номер — по-прежнему производная от ID** (аксессор, доп. колонки нет), но **нумерация начинается
   со 100**: миграция перезапускает последовательность, первый договор — `00100`. Цена: последовательность
   перезапускается, а не сдвигается за существующие строки — база пересоздаётся (`migrate:fresh`).
3. **Поиск по номеру** — SQL-выражением по ID, приведённому к тексту с ведущими нулями (колонки нет).
4. **Форматы значений**: даты — «1 октября 2026»; сумма — «6 000» без знака рубля (шаблон дописывает
   «рублей» сам), копейки печатаются, если есть («6 000,50»). Строк акта — по числу позиций; номер
   строки идёт в колонку «№ п/п» от 1 по порядку списка.
5. **Шаблон** — `storage/app/private/template/storage_contract.docx`, 10 ключей: `contract_num`,
   `created_at` ×3, `user_fio` ×3, `user_phone`, `starts_on`, `ends_on`, `price`, строка акта
   `item_id` / `item_name` / `item_desc`. Файл открыт в git (`!template/**`) — иначе на выкладке его нет.

## Как устроено

`StorageContractDocumentService` (домен Storage) читает шаблон с диска из `config/storage_document.php`,
подставляет значения и отдаёт байты; значения собирает чистый `App\Support\Storage\ContractDocumentValues`
(`forContract` — скалярные поля, `items` — строки акта с нумерацией); русские даты — `RussianDate::dayWithYear`,
сумма без рубля — `Money::amount()`. Кнопка на карточке правки возвращает `StreamedResponse`, Livewire
превращает его в скачивание файла «Договор хранения №00100.docx».

## Проверки

- Красный прогон: `Class "App\Support\Storage\ContractDocumentValues" not found` (6), `Target class
  [App\Services\Storage\StorageContractDocumentService] does not exist` (3), «1 is not ≥ 100» (2), кейс
  кнопки падал на заготовке `dd()`.
- Зелёный: 12 кейсов тест-листа, полный сьют `670 passed (2162 assertions)` (было 658), PHPStan — 0 ошибок,
  Pint — чисто. На живой Postgres-базе: миграция применена, новый договор — `id=100` (`00100`), печать
  договора без позиций даёт документ без плейсхолдеров.
- Отклонения от плана (записаны в план): тесты идут на SQLite — `ALTER SEQUENCE` и `lpad` там не работают,
  поэтому миграция ветвится по драйверу, а поиск использует переносимое `('00000' || cast(id as text)) like ?`;
  добавлена ветка «договор без позиций» (`deleteRow` — в тест-листе кейса не было).
