# Хранение колёс: домен Storage

> Sources: Реализация в backend, 2026-09-17; 2026-09-18
> Raw: [storage-contracts](../../raw/project/2026-09-17-storage-contracts.md); [номер, клиенты, кнопка из записи](../../raw/project/2026-09-18-storage-contract-number-and-clients.md); [печать договора](../../raw/project/2026-09-18-storage-contract-print.md)

## Overview

Сезонное хранение колёс — **отдельный домен Storage**, не часть домена Booking: договор заводится
на клиента (`users`) и **ссылки на запись не имеет** (колёса часто привозят без визита; от `booking_id`
сознательно отказались и когда появился сценарий «сдал колёса при визите» — ADR 0026, пометка 2026-09-18).
Договор несёт срок от/до, стоимость (снимок, вводится оператором) и позиции — что именно оставлено.
Заводит и закрывает договор оператор из панели; закрытие — выдача колёс клиенту.

В прайсе услуг есть категория «Хранение» (`ServiceCategory::Storage`) — это разовая услуга, а не
договор: расчёт стоимости договора по прайс-кубу не подключён (ADR 0026). По этой же категории
в форме записи появляется кнопка «Создать договор хранения» (см. «Договор из записи»).

## Таблицы

| Таблица | Назначение | Ключевые поля |
|---------|------------|---------------|
| `storage_contracts` | Договор хранения | `user_id` (FK users, restrict), `starts_on` / `ends_on` (date), `price` (копейки, `MoneyCast`), `status` (active/closed), `closed_at` (дата выдачи), `operator_id` (FK admins) |
| `storage_items` | Позиции — что оставлено | `storage_contract_id` (cascade), `name`, `description` (text nullable) |

Модели — `App\Models\Storage\StorageContract` (belongsTo `User`, `Admin`-оператор, hasMany `items`),
`StorageItem`; у `User` — `hasMany storageContracts`. Енам состояния — `StorageContractStatus`
(`Enums/Storage/`). Деньги — копейки в БД, рубли в форме (ADR 0013).

## Правила

- **Срок.** `starts_on` / `ends_on` — даты; «до» раньше «от» отклоняется (`afterOrEqual`), равенство
  допустимо: сдал и забрал в один день — нулевой срок.
- **Стоимость** — одна сумма за весь срок, вводит оператор (снимок; изменение прайса договор не
  затрагивает). Рубли в форме, копейки в БД.
- **Позиции** — минимум одна: «что оставлено» есть суть договора; наименование обязательно, описание
  («особенности»: комплектность, повреждения, метки) — нет.
- **Состояние.** Новый договор — `active`; закрытие (выдача колёс) ставит `closed` и дату `closed_at`,
  повторно закрыть нельзя. Автоматики по срокам нет: просрочка видна по `ends_on` у активных.

## Номер договора

Номер — **производная от ID**, а не колонка: аксессор `StorageContract::getNumberAttribute()`
(`str_pad($id, 5, '0', STR_PAD_LEFT)`), договор 7 → `00007`. ID не меняется, а копия в БД завела бы
второй источник правды. Виден в листинге первой колонкой и в заголовке карточки
(«Договор № 00042 — Петров Иван»).

**Нумерация начинается со 100**: отдельная миграция перезапускает последовательность ID, поэтому
первый договор — `00100`. Последовательность именно перезапускается, а не сдвигается за существующие
строки: на базе с уже заведёнными договорами (id ≥ 100) следующая вставка упадёт на дубле ключа —
базу пересоздают (`migrate:fresh`).

В листинге договор **ищется по номеру** (`StorageContractsTable`): и по «00101», и по цифрам без
ведущих нулей. Колонки под номер нет, поэтому поиск идёт SQL-выражением по ID, приведённому к тексту.

## Печать договора

Кнопка «Распечатать договор» на карточке правки отдаёт **.docx** — договор и акт приёма-передачи
(имя файла «Договор хранения №00100.docx»; конвертера PDF в проекте нет). Скачивание работает через
Livewire: страница возвращает `StreamedResponse`, Livewire превращает его в эффект скачивания.

Заполнение шаблона — **пакет `phpoffice/phpword`** (`fixBrokenMacros` склеивает run-ы, расколотые
Word'ом; `cloneRow` размножает строку таблицы и нумерует все её макросы):

| Слой | Класс / файл | Что делает |
|---|---|---|
| Значения | `App\Support\Storage\ContractDocumentValues` | чистая функция: поля договора (`forContract`) и строки акта с нумерацией (`items`) |
| Печать | `App\Services\Storage\StorageContractDocumentService` | шаблон → значения → `cloneRow` по числу позиций → байты |
| Путь к шаблону | `config/storage_document.php` | диск и путь (`template/storage_contract.docx`) |

Форматы: даты — «1 октября 2026» (`RussianDate::dayWithYear`), сумма — «6 000» без знака рубля
(`Money::amount()`, шаблон дописывает «рублей» сам), копейки печатаются, если есть. Строк акта — по
числу позиций, номер строки (колонка «№ п/п») — от 1 по порядку списка, а не id позиции. Договор без
позиций печатается актом без строк (образец строки удаляется — `cloneRow` на нуле падает).

Шаблон лежит в `storage/app/private/template/` и **открыт в git** (`!template/**` в `.gitignore`
каталога) — иначе на выкладке его нет. Ключей в шаблоне — 10; тест печати проверяет, что после
подстановки в документе не осталось ни одного `${`.

## Договор из записи

Договор заводят и с нуля, и **из записи на шиномонтаж**: в форме записи под составом появляется
кнопка «Создать договор хранения». Её показывает **категория услуги** (`ServiceCategory::Storage`),
не название — название правится в справочнике, категория нет. На создании кнопка сначала сохраняет
запись (валидация + `CreateAdminBooking`, клиент ищется по телефону), затем уводит на форму договора;
на правке запись уже сохранена — кнопка сразу уводит (несохранённые правки формы в договор не попадут).

Предзаполнение идёт **адресом формы** (`#[Url]`: `user_id`, `starts_on` — дата слота, `price` — итог
строки хранения, цена × количество в рублях); собирает значения `App\Filament\Support\StorageContractPrefill`
(`paramsFor(Booking)`, он же `hasStorageService` по состоянию репитера). Связи `booking_id` в договоре
нет — сознательный отказ (ADR 0026).

## Панель

`StorageContractResource` — кластер «Шиномонтаж», группа «Хранение» (`BookingGroupEnum::Storage`).
Форма: клиент (Select со связью, поиск по имени/фамилии/телефону), срок с/по, стоимость, позиции
повторителем **со связью** (Filament синхронизирует строки по id при правке — relation manager не
видит несохранённое, повторитель видит). Статуса в форме нет — закрывает действие «Выдать колёса»
в листинге (видно только у активных). Оператора проставляет страница создания из авторизации.
Листинг: номер, клиент, телефон, срок с/по, стоимость, число позиций, состояние.

Нового клиента заводят, **не бросая заполненный договор**: в шапке формы создания — кнопка
«Создать пользователя», открывающая форму клиента в новой вкладке (раздел «Клиенты» — см.
[Админ-панель на Filament](admin-panel-filament.md)). После создания клиент сразу находится поиском
в поле «Клиент» — Select ищет на сервере, вкладку обновлять не нужно.
