# Запись на шиномонтаж — функциональные требования

- **Дата:** 2026-09-11 (порт из сервиса tireslot, ФТ v0.16; ADR 0012)
- **Статус:** Принято (реализация — волны 0–3 переноса)
- **Источник:** `~/my/imsd-ai/tireslot/documentations/tz/functional-requirements.md`

> Адаптации против tireslot: канал записи — **API `/api/booking` + SPA** (не Livewire); клиент — единая **`users`**; таблицы — с префиксом `booking_`; деньги — VO `Money` (копейки, ADR 0013). Каждая ФТ помечена статусом реализации (✓ реализовано / ◑ частично / ✗ не реализовано).

## 1. Назначение и границы

Запись на шиномонтаж: клиент выбирает услуги, параметры автомобиля и время; мастерская управляет записями, расписанием и справочниками через Filament-панель (кластер «Шиномонтаж»).

Границы v1:
- одна точка (мастерская), без мультифилиала;
- без онлайн-оплаты и предоплаты;
- каналы записи: сайт (SPA через `/api/booking`) + админка (запись по звонку);
- клиент без регистрации, идентификация по номеру телефона;
- посты (подъёмники) в бронировании не участвуют: слот — общий на мастерскую;
- SMS — только код подтверждения записи (dev — заглушка `LogSmsSender`).

## 2. Роли

| Роль | Описание |
|---|---|
| Клиент | Гость, записывается через SPA. Идентифицируется по телефону (единая `users`) |
| Оператор | Сотрудник мастерской (Admin панели): запись по звонку, отметки статусов, закрытие слотов |
| Администратор | Управляет справочниками (услуги, цены), расписанием и настройками. Может совпадать с оператором |

## 3. Глоссарий

| Термин | Определение |
|---|---|
| Услуга | Работа из каталога `booking_services`. Цена — за единицу (1 колесо/шт), количество 1–4 выбирает клиент. Работы прайса — с прайс-правилами, доп. работы — с фиксированной ценой за штуку |
| Комплекс услуг | Готовый набор (`booking_complex_services` + `booking_complex_service_items`): своей цены не имеет; в запись не попадает — хранится только состав |
| Параметр авто | Радиус (R13–R21) и тип (легковая/кроссовер/внедорожник; грузовик — по звонку). Влияют на цену |
| Слот | Часовое окно — строка `booking_slots`, генерируемая планировщиком по шаблону недели. Клиенту не показывается |
| Время начала | Начало записи. Сайт — целые часы; админка v1 — тоже целые часы (любое время — ✗) |
| Закрытие слота | Флаг `is_closed` (+ `close_reason`, привязка `booking_id`) — время недоступно на сайте |
| Снимок записи | Параметры авто и цена, зафиксированные в записи на момент создания (`radius`, `car_type`, `plate`, `total_price`, `booking_items.price`) |
| Код подтверждения | SMS-код (`booking_codes`, хранится только sha256): создаёт ровно одну запись, далее верифицирует отмену |
| Заявка на запись | Выбор клиента, передаваемый целиком при подтверждении. Серверно до подтверждения не хранится; слот заранее не удерживается |
| Запись (Booking) | Бронь на время начала: клиент (`user_id`) + услуги + слот + статус. Сущности «автомобиль» нет — параметры в снимке |

## 4. Функциональные требования

### 4.1 Справочники (администратор)

**ФТ-1. Каталог услуг.** ✓ (волна 3b) — ресурсы панели «Услуги» и «Комплексы услуг»; неактивные не видны клиенту (`/api/booking/catalog`).

**ФТ-2. Ценовые правила.** ✓ (волны 1, 3b) — `PriceCalculator`: точное совпадение (услуга × радиус × тип), нет правил → `base_price`, комбинации нет → `DomainException` 422 (запись по телефону). Итог строки = цена за единицу × количество. Изменение правил применяется сразу к новым записям (снимок). Деньги — `Money`.

**ФТ-3. Расписание.** ◑ — шаблон недели (`booking_schedule_templates`) ✓; сетка `slots:generate` каждые 15 мин, идемпотентна, горизонт из `booking_horizon_days` ✓; час стал нерабочим → строка удаляется только пустая открытая ✓ (предупреждение «N записей» ✗); отклонения — закрытием слотов ✓ (массовое действие на день ✗); перерывов как сущности нет.

### 4.2 Клиентская запись (API + SPA)

**ФТ-4. Выбор услуг и параметров.** ◑ — API готов (`/api/booking/catalog` + `/price`); количество 1–4 (дефолт 4) — константы `PriceCalculator`; UI — SPA (✗, отдельный план в репо frontend).

**ФТ-5. Расчёт цены.** ✓ — `/api/booking/price` (unit-цены каталога); серверный пересчёт при подтверждении.

**ФТ-6. Сетка времени.** ✓ — `GET /api/booking/slots` (карта дней) и `GET /api/booking/slots/{date}` (часы, закрытые помечены). Час обслуживает одну бронь с сайта (слот закрывается); дополнительные записи в закрытый слот — только оператор (закрытие не барьер).

**ФТ-7. Запрос кода.** ✓ — `POST /api/booking/code`: кулдаун 60 с серверно (429, в tireslot был только в UI), SMS через очередь. Запись не создаётся, слот не удерживается, заявка не хранится.

**ФТ-8. Подтверждение и создание записи.** ✓ — `POST /api/booking/confirm`: транзакция + `lockForUpdate` слота, слот закрывается с привязкой, цена пересчитывается сервером, код одноразовый (`used_at`), `idempotency_key`. Повторный submit использованного кода → 200 с существующей записью.

**ФТ-9. Срок действия кода.** ◑ — TTL = `reservation_timeout_min` (verify отдаёт Expired → 409) ✓; крон чистки просроченных кодов ✗.

**ФТ-10. Ограничения записи.** ✓ — `min_lead_time_h` (округление вверх до часа) и `booking_horizon_days` через `Setting::get()`.

**ФТ-11. Детали записи.** ◑ — данные в `BookingResource` (дата, время, состав, цена, клиент); адрес/телефон мастерской — в `settings` (`shop_address`, `shop_phone`), экран — SPA (✗).

### 4.3 Статусная машина

**ФТ-12. Статусы и переходы.** ◑ — статусы `confirmed → arrived/no_show/cancelled`, `arrived → done` реализованы табличными действиями панели и правилом «не перечисленные переходы отклоняются» на уровне UI; единого класса статусной машины нет (переходы — в действиях панели).

**ФТ-13. Неявка.** ◑ — ручная отметка `no_show` ✓; счётчик неявок в карточке клиента ✗.

**ФТ-14. Отмена клиентом.** ✗ — экран «Моя запись» (SPA) не реализован; верификатор отмены — `booking_code_id` — в записи есть.

**ФТ-15. Отмена оператором.** ◑ — отмена с причиной ✓; снятие привязки закрытия слота при отмене ✗.

### 4.4 Закрытие слотов

**ФТ-16. Единый механизм блокировки.** ◑ — закрытие напрямую (слот/действие панели) ✓, чекбоксом при записи оператора ✓ (только свободный слот — чужая привязка не перезаписывается), автоматически при брони с сайта ✓; массовое действие на день ✗; перенос записи и снятие привязки при отмене ✗; создание строки слота при записи на время вне расписания ✗ (оператор выбирает из существующих слотов).

### 4.5 Админка (оператор)

**ФТ-17. Календарь дня.** ✗ — есть список записей (ресурс «Записи» со статус-фильтром); календарь с группировкой по слотам не реализован.

**ФТ-18. Запись по звонку.** ◑ — `CreateAdminBooking`: клиент по телефону (`firstOrCreate` в `users`), состав с серверным пересчётом цены, чекбокс закрытия, `operator_id`, `source=admin`, сразу `confirmed` ✓; любое время начала ✗ (целые часы слота); подстановка госномера/параметров из последней записи клиента ✗.

**ФТ-19. Корректировка цены записи.** ✗ — снимок хранится, правка строк/суммы оператором не реализована.

**ФТ-20. Перенос записи.** ✗.

**ФТ-21. Отметки статусов.** ✓ — arrive/complete/noShow/cancel (причина в модале).

**ФТ-22. Карточка клиента.** ✗ — имя/история/счётчик неявок недоступны (записи клиента видны через `users`).

### 4.6 SMS-подтверждение

**ФТ-23. Код подтверждения.** ✓ — `BookingCodeService::issue/verify`; код не привязан к составу; повторная отправка с кулдауном.

**ФТ-24. Отказоустойчивость SMS.** ✓ — `SendBookingCodeSms` через очередь (tries 3, backoff 10/60); сбой провайдера не блокирует запись.

## 5. Нефункциональные требования

| Код | Требование | Статус |
|---|---|---|
| НФ-1 | Атомарность «слот не закрыт» + создание записи (`lockForUpdate`, код одноразовый, `idempotency_key`) | ✓ |
| НФ-2 | Время отклика сетки/брони в сезонный пик | — (не замерялось) |
| НФ-3 | Справочники и расписание из админки без деплоя | ✓ |
| НФ-4 | Логика записи и закрытия слотов — в одной точке (все каналы) | ✓ — `ConfirmBooking`/`CreateAdminBooking` + общий `PriceCalculator`/`GenerateSlotGrid` |
| НФ-5 | Сбой SMS не влияет на консистентность броней | ✓ |

## 6. Вне рамок v1

Онлайн-оплата; мультифилиал; посты; напоминания (SMS/мессенджеры); телеграм-бот; личный кабинет; чат/карты; отчёты и аналитика.

## 7. Параметры конфигурации (`settings`, значения по умолчанию — `SettingKeyEnum`)

| Параметр | Ключ | По умолчанию |
|---|---|---|
| Срок действия кода подтверждения | `reservation_timeout_min` | 15 мин |
| Порог свободной отмены клиентом | `cancel_free_before_h` | 2 ч (ФТ-14 ✗) |
| Минимальное время записи до начала | `min_lead_time_h` | 1 ч |
| Горизонт записи | `booking_horizon_days` | 30 дней |
| SMS-провайдер | `SMS_PROVIDER` (env) | не выбран (заглушка `LogSmsSender`) |
