# 0023. Каталоги доменного слоя: действия в `Actions`, службы областей в `Services`

- **Статус:** Superseded (заменён конвенциями backend — `CLAUDE.md`)
- **Дата:** 2026-09-09 (перенесён из tireslot 2026-09-12, исходный №0010)
- **Связанные ADR:** 0014

## Контекст

Единая доменная логика для обоих каналов требовала порядка в слое, но классы не имели единого стиля: разные имена классов (Creator/Calculator/Generator), разные методы (`confirm`/`quote`/`generate`).

## Решение

Доменный слой разведён по гранулярности: однооперационные действия — `{Глагол}{Существительное}Action` с единственным методом `handle()`, службы областей (коды, доступность) — в `Services`.

## Почему (альтернативы)

Плоский `Services` с разнородными именами не давал словаря для новых операций.

## Последствия

**Superseded при переносе в backend:** гранулярность «одно действие → один класс» сохранена, но конвенции backend требуют иного стиля — Actions без суффикса `Action` и с методом `execute(DTO)` (см. `CLAUDE.md`, раздел «Слои»); расчёт цены — сервис `Services\Booking\PriceCalculator` (правило «Action не вызывает Action», ADR 0001 backend). Имена порта: `GenerateSlotGrid`, `ConfirmBooking`, `CreateAdminBooking`.
