# 0007. Описание товара живёт на модели, не на товаре

- **Статус:** Accepted
- **Дата:** 2026-08-21
- **Связанные ADR:** 0005 (опциональные колонки импорта)

## Контекст

Описание товара приходило из XLSX и хранилось на каждой позиции (`tire_products.description`, `wheel_products.description`) — у всех типоразмеров одной модели дублировалось одно и то же описание (производитель, страна, год). Это раздувало строки и противоречило структуре: описание — свойство модели (семейства), а не типоразмера.

## Решение

Колонки `description` удалены из `tire_products` и `wheel_products`. Описание из единой колонки XLSX `description` (text) пишется в `product_models.description` — один раз на модель, общее для всех её товаров. Обновляется при каждом импорте строки с колонкой (последний выигрывает); колонки нет в файле — не трогается (ADR 0005). Старые колонки описаний (vendor_description и пр.) и JSON-структура на товаре упразднены, DescriptionBuilder удалён.

## Почему (альтернативы)

- **Оставить описание на типоразмере** — дублирование данных по числу размеров модели, риск расхождений, лишний вес; импорт всё равно переписывал его одинаковым значением.
- **Отдельная сущность описаний** — избыточность: описание одно на модель, таблица не дала бы ничего, кроме лишнего слоя.

## Последствия

Проще: одна запись на модель, данные консистентны, удаление дублей. Сложнее: описание нельзя развести по типоразмерам (если когда-нибудь понадобятся разные описания на размеры — вернётся колонка на товаре или справочник). API-контракт админки шин/дисков потерял поле description (осталось у модели) — фронт админки должен брать описание из модели.
