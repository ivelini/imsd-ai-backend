# Архитектурные решения (ADR)

База решений проекта — «почему система устроена так». Полные правила: правило `adr.md` (глобальное), шаблон — `0000-template.md`.

Когда писать: решение, которое иначе переоткроют или переспорят (новый человек, AI-агент, рефакторинг). Не писать: детали реализации, решения без развилки, пересказ механики.

## Раскладка

Решения лежат по доменам — папка соответствует домену в `app/`:

| Папка | Что решает |
|---|---|
| `common/` | сквозные решения: слои, кеш, панель, деньги |
| `catalog/` | товары, цены, импорт, фильтр, SEO |
| `booking/` | запись на шиномонтаж |

**Нумерация сквозная:** `NNNN` — следующий свободный номер по порядку, независимо от папки. Номер не переиспользуется и не меняется, если решение переезжает в другую папку — на номера ссылаются код, вики, планы и ТЗ. Новый домен — новая папка, номера продолжаются общим счётом.
