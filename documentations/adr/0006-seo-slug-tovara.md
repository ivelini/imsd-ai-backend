# 0006. SEO-формула slug товара: brand-model-размер-индекс

- **Статус:** Accepted
- **Дата:** 2026-08-21
- **Связанные ADR:** 0001 (чистые алгоритмы в Services)

## Контекст

Изначально slug шины строился только из характеристик (`215-60-16-studded`) — стабильный URL, не зависящий от названий. Заказчик потребовал человекочитаемые SEO-адреса: `gislaved-soft-frost-200-195-55-r16-91t-studded`. Формулы slug — в общем билдере для импорта и админки (ProductSlugBuilder/ProductSlugService), чтобы ручное создание и импорт давали одинаковые адреса.

## Решение

Slug шины = `{brand-slug}-{model-slug}-{width}-{profile}-r{diameter}-{load}{speed}[-studded][-runflat]` (lowercase, части по наличию, коллизии — суффикс `-2`). Slug диска = прежняя формула, но точки → дефисы. Slug модели = только из названия модели (`soft-frost-200`), без префикса бренда; уникальность — парой (brand_id, slug), совпадение между брендами допустимо. Формула — чистая функция (ADR 0001), БД-обвязка достаёт slug бренда/модели по id.

## Почему (альтернативы)

- **Оставить стабильный slug из характеристик** — адрес не несёт смысла для пользователя и поисковика; требование SEO-адресов явное.
- **Slug из полного названия товара** — нестабилен при любом переименовании и ломает URL массово; компромисс — только brand + model (редко меняются) + характеристики.
- **Разные формулы для админки и импорта** — рассинхрон URL для одного товара в зависимости от источника создания — отвергнуто.

## Последствия

Проще: адреса читаемы, содержат ключевые слова. Сложнее: slug нестабилен при смене названия модели или бренда — URL карточки меняется при переимпорте; существующие товары получают новые адреса (SEO-редиректы — ответственность фронта). Пересмотрим при введении «вечных» URL (slug-псевдонимы) или если переименования моделей станут частыми.
