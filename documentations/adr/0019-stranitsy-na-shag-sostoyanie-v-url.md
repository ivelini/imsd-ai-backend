# 0019. Публичный сайт: страницы на шаг записи, состояние заявки в URL и сессии

- **Статус:** Superseded (заменён ADR 0012)
- **Дата:** 2026-09-08 (перенесён из tireslot 2026-09-12, исходный №0006)
- **Связанные ADR:** 0012, 0015

## Контекст

Публичный сайт — самостоятельный Livewire-сайт в монолите; поток «сначала время, потом услуги». Встали две развилки: строить поток одним степпер-компонентом или отдельной страницей на шаг, и где держать состояние заявки между шагами — до подтверждения кода БД не пишется (ADR 0015), данные должны переживать F5 и «назад» браузера.

## Решение

Каждый шаг — отдельный full-page Livewire-компонент; URL совпадают со структурой мокапа. Состояние: выбор времени и услуг — в query-параметрах URL; персональные данные — черновик в сессии. Экраны результата — редирект с сессионной пометкой: ID записей в публичные URL не попадают, доступ — только через верификацию телефоном и кодом.

## Почему (альтернативы)

Единый степпер терял соответствие экран → маршрут и разбухал; черновик целиком в сессии не давал URL отражать выбор; публикация ID в URL открыла бы чужие записи.

## Последствия

**Superseded:** в backend публичный канал — API + SPA (ADR 0012): сервер заявку не хранит (соблюдено), а состояние визарда живёт на стороне SPA (URL/стор клиента) — договорённости этого ADR переносятся в план frontend-репо. Серверные инварианты сохранены: запись только по коду, ID в публичных контрактах минимально.
