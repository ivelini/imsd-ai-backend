# 0015. Запись создаётся только при подтверждении кода

- **Статус:** Accepted
- **Дата:** 2026-09-04 (уточнено 2026-09-08; перенесён из tireslot 2026-09-12, исходный №0002)
- **Связанные ADR:** 0014, 0016

## Контекст

Клиент выбирает время и вводит данные. Классический сценарий: создать запись в промежуточном статусе и держать слот на таймаут, пока клиент подтверждает SMS-код.

## Решение

Запись создаётся только при вводе кода — сразу в статусе `confirmed`; код одноразовый (`used_at`) и остаётся верификатором отмены. Заявка до подтверждения не хранится: клиент передаёт актуальный выбор при вводе кода, цена пересчитывается сервером (`PriceCalculator`) и фиксируется снимком в записи — изменение выбора после запроса кода не перевыпускает код. Слот не удерживается. Из админки запись создаётся сразу (`CreateAdminBooking`). Повторный submit использованного кода возвращает созданную запись (200), а не создаёт новую.

## Почему (альтернативы)

Слот-час не ограничен по числу записей (ADR 0016) — удерживать его за клиентом нечего. Промежуточный статус дал бы висящие записи в календаре и крон истечения без защиты времени. Хранение заявки вместе с кодом требовало перевыпуска кода при каждом изменении выбора — каждая SMS это расходы. Цена: клиент, подтвердивший поздно, может получить отказ «время недоступно» (409) — обрабатывается как повторный выбор.

## Последствия

Статусная машина без промежуточного состояния, календарь содержит только реальные записи; одна SMS на цикл записи. Пересмотрим, если появится лимит на час или посты — тогда вернётся смысл резерва с удержанием слота.
