# 0002. catalog_prices — полная цена города и единый матчинг наценок

- **Статус:** Accepted
- **Дата:** 2026-08-13
- **Связанные ADR:** 0001

## Контекст
`catalog_prices` предрассчитывает цены stock × city после импорта, но давал неполную картину: наценка города (стоимость доставки) применялась отдельно, в четырёх местах с разными механизмами выбора правила; сроки доставки в таблице не заполнялись; каждый импорт товаров пересчитывал все пары stock × city.

## Решение
`catalog_prices` — источник полной цены для города: `price` = наценка склада + наценка города (`city_price_rules`), сроки — стабильный диапазон (расписание склада + время доставки города), не зависящий от момента пересчёта. Выбор правила наценки — единственная чистая функция `MarkupRuleMatcher`, которой делегируют все пути: массовый пересчёт, карточка товара, сервис стоимости доставки. После импорта товаров пересчитываются только затронутые остатки; полный пересчёт — только когда меняется география (импорт точек). Из API остатков убран отдельный `delivery_cost`: цена уже полная, раздельный возврат задваивал бы её при суммировании.

## Почему (альтернативы)
- Снимок «здесь и сейчас» в сроках доставки: пересчёт редкий (импорт раз в неделю), значение устаревает после полуночи — предрасчитанная таблица врёт.
- Оставить наценку города вне таблицы: правило выбора разъезжается по потребителям (было 4 копии, одна уже разошлась в деталях), каждый дублирует матчинг.
- Полный пересчёт на каждый импорт: линейно растёт с stock × city, хотя импорт товаров меняет только часть остатков.
- Сохранить `delivery_cost` в ответе остатков: при включении наценки в цену сумма на клиенте задваивалась.

Цена: изменение `city_price_rules` требует полного пересчёта (закрыто импортом точек); контракт админского API остатков изменился (поле удалено).

## Последствия
Проще: один источник правила наценки (тестируется Unit), полная цена города без вычислений у потребителей, повторные импорты дёшевы. Сложнее: админский фронт должен перестать суммировать `delivery_cost`; контракт API остатков изменён. Пересмотрим: при появлении других типов правил (промо, сезонные) — расширение matcher; если пересчёт станет узким местом — пересмотр стратегии.
