# API — Стандарты оформления

> Версия: 1.0
> Базовый URL: `/api`, `/api/admin`

---

## 1. Формат запроса

### 1.1. Content-Type

Все запросы с телом — `application/json`.

### 1.2. Авторизация

| Заголовок | Значение | Где |
|-----------|----------|-----|
| `Authorization` | `Bearer {token}` | Авторизованные пользователи и админы |
| `X-Device-Id` | `uuid` | Для гостевой корзины/избранного/сравнения |

Токен выдаётся при `POST /api/auth/login`. Живёт, пока не вызван `POST /api/auth/logout`.

### 1.3. Пагинация

Параметры query-string:

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|-------------|----------|
| `page` | int | 1 | Номер страницы |
| `per_page` | int | 48 | Элементов на странице (макс. 100) |

### 1.4. Сортировка

| Параметр | Тип | Описание |
|----------|-----|----------|
| `sort_by` | string | Поле сортировки: `price`, `brand`, `diameter`, `created_at` |
| `sort_dir` | string | Направление: `asc`, `desc` |

## 2. Формат ответа

### 2.1. Успешный ответ — один объект

```json
{
    "data": { ... }
}
```

### 2.2. Успешный ответ — коллекция с пагинацией

```json
{
    "data": [ ... ],
    "meta": {
        "current_page": 1,
        "last_page": 10,
        "per_page": 48,
        "total": 480
    }
}
```

### 2.3. Каталог с фасетами

```json
{
    "data": [ ... ],
    "facets": {
        "diameter": {
            "values": [
                { "value": 16, "count": 120 },
                { "value": 17, "count": 89 }
            ]
        },
        "season": {
            "values": [
                { "value": "winter", "count": 95 },
                { "value": "summer", "count": 114 }
            ]
        }
    },
    "meta": {
        "current_page": 1,
        "last_page": 10,
        "per_page": 48,
        "total": 480
    }
}
```

### 2.4. Ошибка

```json
{
    "message": "Товар не найден",
    "errors": {
        "field_name": ["Описание ошибки 1", "Описание ошибки 2"]
    }
}
```

HTTP-статусы ошибок:

| Статус | Когда |
|--------|-------|
| 422 | Ошибка валидации (`FormRequest`) |
| 403 | Нет прав |
| 404 | Ресурс не найден |
| 409 | Бизнес-ошибка (`DomainException`) |
| 429 | Превышен rate limit |
| 500 | Внутренняя ошибка сервера |

## 3. Структура ресурсов

### 3.1. Принципы

- Все ответы оборачиваются в `data` (Laravel API Resource)
- Для списков — коллекции с пагинацией
- Дата/время — в ISO 8601
- Цены — целые числа (копейки не передаются)
- Булевы поля — `true` / `false`

### 3.2. Формат полей

| Тип данных | Формат | Пример |
|-----------|--------|--------|
| `decimal` | Целое число (копейки в `price`) не передаются | `5600` |
| `boolean` | `true` / `false` | `true` |
| `datetime` | ISO 8601 | `2026-07-27T14:30:00Z` |
| `date` | ISO 8601 | `2026-07-27` |
| `enum` | Строка (value из enum, не label) | `"winter"` |
| `null` | Не передавать или явно `null` | — |

### 3.3. SEO-блок

Страницы каталога и карточки товара могут содержать SEO-блок:

```json
{
    "data": {
        "...": "...",
        "seo": {
            "title": "Купить шины 205/55 R16 в Москве",
            "h1": "Шины 205/55 R16",
            "description": "Шины 205/55 R16 …",
            "canonical": "https://...",
            "breadcrumbs": [
                { "title": "Главная", "url": "/" },
                { "title": "Шины", "url": "/catalog/tires" }
            ]
        }
    },
    "meta": { ... }
}
```

## 4. Ограничения (Rate Limiting)

| Тип запроса | Лимит |
|-------------|-------|
| Публичные эндпоинты | 60 запросов/мин |
| Авторизованные пользователи | 120 запросов/мин |
| Админ-панель | 120 запросов/мин |

---

## 5. Обработка ошибок

### 5.1. Валидация (422)

Business-логика проверяется в `FormRequest`. Ошибка возвращается в формате:

```json
{
    "message": "The given data was invalid.",
    "errors": {
        "email": ["Поле email обязательно."],
        "password": ["Пароль должен содержать минимум 8 символов."]
    }
}
```

### 5.2. Бизнес-ошибки (409)

Бизнес-правила проверяются в `Preconditions`. Ошибка — `DomainException`:

```json
{
    "message": "Товар отсутствует на складе",
    "errors": {}
}
```

HTTP-статус: 409 (Conflict).

### 5.3. Ресурс не найден (404)

```json
{
    "message": "Товар не найден",
    "errors": {}
}
```

### 5.4. Нет прав (403)

```json
{
    "message": "Доступ запрещён",
    "errors": {}
}
```

## 6. Версионирование

API без префикса версии (`/api`, не `/api/v1`). При обратно-несовместимых изменениях — добавляется префикс версии.

---

## 7. Публичные vs Административные эндпоинты

| Префикс | Роут-файл | Доступ |
|---------|-----------|--------|
| `/api` | `routes/api.php` | Публичные + Sanctum (авторизованные) |
| `/api/admin` | `routes/admin.php` | Sanctum (только администраторы) |

---

## 8. Именование эндпоинтов

- Ресурсы — во множественном числе: `/api/products`, `/api/orders`
- Вложенные — через точку: `/api/products/{product}/images`
- Действия — глаголы: `/api/cart/calculate`, `/api/orders/{id}/cancel`
- Параметры фильтра — в query-string: `/api/catalog/tires?width=205&diameter=16`
