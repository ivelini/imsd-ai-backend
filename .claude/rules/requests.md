# Requests

## Отдельный FormRequest для эндпоинта с частичным контрактом

Эндпоинт принимает только часть контракта FormRequest'а — создавай отдельный request, не переиспользуй «жирный». Пример: show шины использует только `city_id` из `TireProductIndexRequest` (21 параметр) → создан `TireProductShowRequest` с одним правилом.

**Почему:** переиспользуемый request тащит в контракт эндпоинта лишние поля — Scramble документирует параметры, которые эндпоинт игнорирует (потребитель API ожидает фильтры в show, а они не работают), а лишняя валидация даёт ложные 422.

**Как применять:** переиспользование допустимо, когда эндпоинт принимает весь контракт (index + его request; import — один request на несколько источников данных). При частичном использовании — отдельный класс. Scramble показывает каждый параметр из `rules()` в документации эндпоинта — если эндпоинт его игнорирует, это баг в документации.
